## 玩家主动模拟比赛

开赛页面“模拟本场”读取选定职业、进阶和当天已报名比赛，调用 PlayerSimulation.Run。检查当前未完成对局和失败选择，再复用 EntryReason、PrepareSeed、PrepareOpponent；Sample 返回成绩后调用 FinishMatch。获胜正常结算，失利进入 FailureDecision，通关但用时较慢也进入同一选择。平局沿用 ReplayTie。Failure 存在时，CareerScreen.Render 显示原失败选择界面，AdvanceOneDay 等待玩家完成选择。

FinishMatch 先用局部变量比较成绩；失利待选择时仅写入 Failure.Result、Failure.Opponent，清理 PendingMatchId/PendingSince 并保存。正式 CareerMatch 的 PlayerFloor、PlayedAscension、PlayerSeconds、Draw、PlayerWon 在此分支返回后赋值。奖励、关注、评分、荣誉、Fixture、CompleteMatchDay、国运、行情和战报均沿正式结算继续执行。原失败成绩保存在待选择对象中，历史采样读取正式 Results。

FailureAction 的同种子/新种子按钮调用 MatchFailure.Retry，再沿 GameBridge.StartMatch 进入实际游戏。模拟失利按 Failure.Result.CharacterId 读取本次职业，并传入 PlayedAscension（缺省取 Ascension）；同种子恢复原对手成绩，新种子重新准备对手。RestoreMatch 在每次选择及确认时读取原种子、原对手快照，避免新种子开局中断后混用新对手与原失败。GameBridge 开局成功才清除 Failure；准备失败仍保留原决定。Confirm 读取原成绩和 Simulated 标记后，传入 confirmFailure=true 正式结算。

单人只有产生该场正式结果时切换结算，加赛留在开赛页面。多人CareerScreen._Process比较更新前后最后一条MatchId，新结果为Simulated且PendingSettlementId对应时切换一次；普通Revision更新及重复快照不切换。

正式比赛FinishMatch在ResolvePlayerFixture后调用EsportsWorld.CompleteMatchDay，再处理个人合同、战报和SettlementRecords.Capture。CompleteMatchDay与EndDay共用SettleDay；前者只模拟当天尚未完成的NPC对阵，后者仍处理到期未出场的玩家席位。TeamPreparations.Complete按原CompletedRounds扣除已完成轮次；AdvanceCompetition生成后续签表、结算整届，联赛收官日再CreateFinals。AddRound按轮次确认签表是否已生成，重复日结算不再增加相同轮次。当前日期不变，其他同日未完成玩家比赛保留，旧历史结算快照不重写。

FinishMatch 的新战报还通过 WorldEvents.FixtureFacts 追加本赛事当日同轮具体成绩，写入 RelatedFacts、SourceBody、Body；未完成的另一场玩家对阵明确标记尚未完成。奇数季世界总决赛首轮早于洲际杯一天，偶数季没有世界总决赛；AdvanceToMatch 按真实已报名日期停止，不能把“必须先进入洲际杯”当作正确性条件。

Sample 排除退赛和没有正数用时的历史，按 MatchId 去重。有真实记录时仅使用真实记录，否则使用先前模拟记录；优先本次挑战进阶，没有同进阶记录则使用全部可用记录。通关概率等于历史通关比例，通关/失败分别取同类平均用时，失败楼层取失败记录；随机种子使用生涯和比赛种子。

没有可用历史时保证获胜。均值取当前职业选手在该进阶的平均通关时间，沿用难度倍率和多人半小时增量；对手已通关时，用时最多为对手整数秒减一，符合 Compare 按整数秒比较的规则。对手成绩与时间不改。

Sample 两个分支返回前统一调用 VaryTime(d, match, result)，输入为原算法产生的通关情况、楼层和基准用时，返回用时浮动后的 RunPerformance。通常从基准用时的97%至103%均匀抽取。双方通关时先用 MatchRules.Compare 判断原胜负：原本获胜，上界收窄到对手整数秒的前一个可表示浮点数；原本失利，下界至少为对手整数秒加一；原本平局，返回原用时。通关情况或失败楼层决定胜负的场景使用完整浮动范围。首次模拟先按原规则得到必胜基准，再执行同一浮动函数。

用时随机种子为 WorldId + ":player-simulation-time:" + match.Seed，通关及楼层继续使用原 ":player-simulation:" 随机序列。不同比赛产生小幅用时变化，同一输入和存档恢复得到相同成绩。VaryTime 每次调用执行常数次数的数值比较，非平局时创建一个独立 Random 并抽取一次；历史筛选仍按原输入线性遍历。Sample 的结果由单人 Run → FinishMatch 和多人 Apply → Settle 使用，随后进入原奖励、战报、结算快照与保存流程。用时随机函数仅返回值，缓存范围为空，额外资料复制、保存和广播次数均为零。已完成比赛保留原记录，待赛场次在执行模拟时应用当前规则。

多人 propose-simulate 经现有成员确认后，Prepare 建立比赛参数；随机职业按本场种子和成员身份选择，合并参与成员历史后调用 Sample，再由 Settle 处理。失利时 Run.Phase=decision，Terminal 保存原团队成绩；个人 Results、资金分配及 Settlements 在正式确认后写入。房主选择重赛建立原 start 提议，原 Terminal 保留到全队确认；取消提议后仍可确认原失败。执行 start 时在命令副本内释放旧 Run，由 Prepare 建立真实对局；准备失败沿 Apply 返回原对象。请求校验、重复收据、Revision、检查点和广播共用原命令流程。

## 逐场国运与国家发展

FinishFixture 确认胜负后调用 NationalFortune.Confirm。世界总决赛各轮胜/负贡献为 10/5、20/10、60/30、120/60、390/90；洲际杯为 10/5、15/10、35/20、120/30；世界杯为 30/15、90/60、240/60。三届冠军沿途总额分别为 600、180、360。国内比赛、约战不产生国运。

团体赛每局先发基础贡献，整轮确定后给晋级队伍补差额；合作队伍一份成绩代表三席，不因二人或四人扩大国家总奖励。弃权局没有基础贡献，晋级方保留晋级部分。每点国运提供 20 Credits（$200）个人奖励，国家储备仍为 2 Credits；最终名次结算不重复发放。旧档已生成的赛事继续使用原整届结算法，新生成赛事使用逐场算法。

贡献先补每季 120 点维护，剩余按经济 40%、社会 25%、民生 35% 进入建设余额；升级成本随等级递增，不足余额保留。换季先用上季贡献与等级计算 GDP，再每类支付 40 维护，不足类别随机降低一项非零指标。随机选择由生涯、国家、赛季确定，读档不重新抽取。赛程和赛制保持原逻辑。

WorldEvents 每3—6天在有素材的题材中按权重抽取：国运发展、市场动态各1.5，其余八种人物题材各1；具体模板数量不影响题材概率。不增加轮换或本轮防重复。原有人物题材14天和人物42天间隔保留；市场使用NewsDay保持7天间隔，仅取最近7天尚未报道的最多8条事件。国运候选仍为最近7天有未报道贡献的国家，抽中后不再进行额外30%判定。不增加事件保存节点。结算附本场国运及实际等级变化；国家发展页面展示九项等级、描述、GDP、维护余额和最近变化。

## 商城、关注与交易界面

### 关注、合同与个人收入

CareerAudience 是 MatchGain、ChampionGain、Followers、Title、QuoteMultiplier、ClubMultiplier、PromotionGain 的统一入口。普通比赛奖金保持原值，新增选手合同的签字费基准、工资、胜场和达标奖金翻倍；已保存的选手工资和预约合同不重算。赞助收入按下面的持续合同规则计算。自建俱乐部成立费用为 20,000 Credits（$200,000），新建俱乐部真人工资与胜场奖金显式记录 280/200，旧字段缺省为 140/100，避免读档改动旧合同。

比赛获胜基础关注：联赛600、洲际杯2000、世界杯3000、世界总决赛及大师赛5000；国际赛按第1—5轮乘1、1.5、2、3、4，平局为40%，失利沿用少量楼层奖励，约战与弃权不发。冠军额外关注由 ChampionGain 统一提供：联赛10万、洲际杯15万、世界杯50万、世界总决赛100万。

SeasonCeremony.Close 先按颁奖前关注计算每个奖项 AudienceReward，再统一增加 NPC 关注；玩家及多人由原收据领取。联赛MVP取30万与有效关注8%的较大值，赛季最佳取50万与12%的较大值，年度最佳取80万与50%的较大值；有效关注=F/(1+F/5000万)。新秀奖20万/30万，俱乐部奖不额外发个人关注。年度奖仍每四季举行。历史记录没有 AudienceReward 时继续读取原90/240，不追补旧奖励。

个人赞助倍率=(1+F/100000)^0.6390841180914144；5000万与1万关注的倍率之比为50。俱乐部倍率=(1+F/100000)^0.662800438550683；1000万与1万关注之比为20。新旧赞助均在付款时计算倍率；OwnedSponsor.AudienceVersion 不再分流公式。ClubAudience.Total 返回球队独立关注加现役前三名关注之和的20%；通过CoachLineups.Coach排除原有及转任教练，仍在首发/轮换岗位的兼任教练按选手计算；转会不写入球队独立关注。普通俱乐部每轮通过 AudienceReceipts 去重，玩家自建俱乐部仍由原 SettleResults 收据处理。轮次胜/负2000/500，洲际杯另乘2及晋级倍率；俱乐部冠军联赛30万、洲际杯50万；其余名次关注为旧基础值100倍，洲际杯继续额外翻倍。

SponsorIncome 统一基础金额迁移及个人/普通俱乐部金额计算。个人荣誉档次=1+min(7,本人非联赛冠军数)，兼容 player 与当前多人真人编号；稳定支持基础赛季款/胜场款=320/20 Credits，成绩奖励140/65，品牌推广200/25，均乘报价时荣誉档次。新合同记录基础金额；旧已签或待选合同在 Upgrade/RefreshOffers 按现有方案、当前荣誉档次确定基础金额一次。没有方案名的早期个人合同用历史报价除以转换时倍率确定基础金额，保留当前收入规模。普通俱乐部按球队类型基础3200/2000/4200/1600、已有冠军乘2确定基数一次。界面纯读取不会写入基础金额；显示和付款都调用相同计算入口，不将旧报价再乘一次倍率。

个人首次签约支付本季款；后续赛季通过原 SeasonStart 付款，胜场通过 PlayerMatch 付款。已付赛季不补差额，重复赛果不重复付款。个人两季合同在 RefreshOffers 到期时自动延长两季；已结束历史合同不恢复。当前合同也提供三种下期报价，原28天邀请有效期继续适用；选择只保存 NextOffer、不扣款或提前付款，可在生效前重新选择。到期将旧合同结束、所选合同生效，再由原 PaidSeason 处理当季款；没有选择则延续原品牌及基础金额。自建俱乐部沿用原56天自动续约，周结与胜场按当时关注乘已存基数。赞助页面显示当前预计金额、自动续约说明和已选下期方案。旧工资、签字费、比赛奖金、已发放资金不受此迁移影响。

商品、耐用品活动、宣发共用 ConsumerEngine。受邀 NPC 必须可联系且好感至少5，人数由商品规定；同一 NPC 每季首次受邀增加规定好感，后续加1。普通消费不涨粉；宣发每项每季三次，增量为显示美元价格/2/(1+0.5×本季次数)。四项各三次合计花费135万美元，增加487500关注。个人内容和社区活动基础关注乘20。

### 品牌赛事影响与新闻素材

CareerMarket.Fixture 在整个对阵已完成、非平局且未 MarketSettled 时执行一次；纯轮空对阵不产生价格信号。MarketDynamics.Links 统一读取有效个人、普通俱乐部、自建俱乐部赞助及多人 MarketSponsors 委托，按品牌/对象/俱乐部标识去重；Partners 复用这些关系构建搜索和关注基准所需名单。

每日外汇标准差0.8%，2%概率叠加1.5—3.5倍标准差冲击，额外冲击限于±2.8%；均值回归系数0.03，累计国运差×0.0000012及当季国运差×0.000003合计限于±0.0005。世界杯、世界总决赛晋级+1、冠军另+2、淘汰按轮次−0.5^(轮次−1)，决赛败者0；两国信号差每日合计限于±4，每单位对应1%对数变化。Fixture 在正式赛果确认时应用本日合计的增量，下一天只生成日常变化并清零合计。洲际杯通过国运间接影响外汇。报价为1人民币兑换的外币数量；外币国减中国的国运差和赛事信号在定价时取负号，上涨表示人民币升值，做多按报价上涨获利。旧 PricingVersion=0 遗留信号加载时计价一次，已有方向、成本、持仓数量与历史收益不重算。失败待选择和同成绩加赛不进入 Fixture，不影响原重赛流程。

MarketExecution按买卖两侧分别累计成交。B为外部行情基准，K为DepthUnits；BuyUnits、SellUnits分别表示本次外部报价以来已买入、已卖出的数量。买入边际价格为B×(1+BuyUnits/(2K))；卖出边际价格为B/(1+3×SellUnits/(2K))^(1/3)。Open按保证金×杠杆反求数量，Close对退出方向积分，返回整笔均价、手续费、到账和净盈亏。差值采用因式分解，保留巨量累计成交后的小额订单精度。做多建仓和做空平仓消费买入一侧；做空建仓和做多平仓消费卖出一侧。拆单沿同一方向的累计数量继续成交。强平买回增加后续买入成本，多仓卖出收入由卖出一侧的承接条件决定。

Apply→Consume写入两侧数量、ExecutionBase、DepthUnits和基准Price，再更新当日历史与Revision。中央行情与止损触发价采用外部基准；下单按钮附近显示两个方向各自的实际均价。强平检查使用Close算出的整笔预计到账，与最初保证金10%比较，覆盖退出成本及手续费。账户结算先记录全部已触发仓位，之后逐笔成交并检查剩余仓位；已入队仓位跳过重复预览。每笔实际到账取零与净值的较大值，手动、止损及强平共用此入口。

MarketNumber以BigInteger保存固定28位小数，整数位随数值扩展，用于成交数量、乘除中间值及手续费。Root从浮点初值开始执行四次扩展精度牛顿迭代；Close先完成全部成本计算，再将非负到账舍入四位并转为decimal账户金额。Net为每种持仓资产复制一个Quote数值对象，按持仓顺序调用同一个Close和Consume，History共享只读。钱包整数部分改为decimal，CareerMoney.Add和CoopRules.AddMoney继续拆分整数及CreditFraction，原JSON整数直接读取。

## 对手成绩与通关用时

MatchRules.Simulate(CareerData, ...) 读取人物、赛事进阶和比赛日期。单人调用 Evaluate，合计基础通关率、长期培养、陪练、临时训练、交流学习与短期状态；多人先由 CircuitWorld.CooperativePerformance 提供队伍身份，再由 TeamChance 对每名队员的因子取平均。两种入口都将最终通关率及防守值交给 SimulatePerformance。直接接收 CareerPerson 的重载也进入同一函数。

SimulatePerformance 用既有 performance 种子先判定通关，再按原 FailureFloor 决定失败位置；这两步的随机数和规则不变。随后调用 CompletionSeconds(professional, chance, cooperative, rng)。该函数只返回完整通关所需秒数，不修改人物、不保存、不同步，也没有个人速度字段或缓存。

| 参数 | 职业选手 | 普通选手及青训 |
| --- | --- | --- |
| 基准秒数 B | 3600 | 5100 |
| 校准通关率 R | 0.2 | 0.5 |
| 正态分布中心 | B × [1 + 0.18 × (R − 本场最终通关率)] + 180秒 | 同左 |
| 标准差 | B × 0.07 | 同左 |
| 截断范围 | 2700—4500秒（45—75分钟） | 3825—6375秒（63分45秒—106分15秒） |

正态样本使用 Box–Muller 计算，超出上述区间就重新取样，避免直接压到边界形成大量同秒成绩。截断会使靠近边界时的实际均值略偏离分布中心。先将样本四舍五入到整数秒，多人再加1800秒；人数不额外放大这项增量。失败用时继续按止步楼层除以50折算。最后 RivalTimeScale 同比缩放：百倍0.75、千倍1、万倍1.5。通关与失败楼层不受速度设置影响；Compare 保留通关优先、双通关比较整数秒、双失败比较楼层的规则。

PrepareOpponent 将成绩保存在 CareerMatch.OpponentWon、OpponentFloor、OpponentSeconds、OpponentPrepared；已有 OpponentPrepared 时直接使用已保存值。CoopRules.Start 也调用同一 Simulate，记录房主决定的对手成绩；暂停和恢复读取既有结果。EsportsWorld.SimulateFixture、CareerEngine 的日常模拟、CircuitPeople 的选拔及 OwnedClubs 的青训考核复用同一入口。LiveMatch/RivalSimulation、CoopLive、结算、赛程、战报及模型事实读取生成后的成绩，不自行抽取新的用时。没有新增存档字段、迁移、保存节点、广播或恢复机制；旧档已准备和已结算的结果不因版本更新重算，后续实际生成的成绩使用新分布。

验证：分布初稿完成84万样本、15840组旧生产程序集通关结果与失败楼层对照、528组生产程序集与测试源码核对；覆盖所有进阶、极端评分、固定种子、禁赛、倍率、训练、已准备旧档、二人与四人队伍及JSON重新读取。随后仅将分布中心增加180秒，生产构建通过，针对最终程序集检查职业/普通各三档概率，每档3000组单人及多人用时。默认千倍职业通关率20%、50%、80%的当前样本均值为62.86、59.64、56.43分钟；全部样本满足原上下限，单人与多人同种子结果相差1800秒。此次参数调整没有重复全量回归，没有调用模型或执行真实Steam联机。逐次耗时与原始结果见本地PERFORMANCE对应章节。

## 多人后台接收期间的原版对局与界面

CoopCoordinator.Tick 先接收网络，再执行 PumpReceived。候选快照在后台持久保存和准备个人视图期间，当前 World / NativeSave 保持原来的配套状态。NativeRun.Update 在 Receiving 时继续 PumpPendingNetwork，暂不依赖未提交快照开始新的大厅状态操作；已经运行的原版战斗仍沿原 NetService 处理。

新局与读档响应、ShouldAllowRunToBegin、BeginSaved 等通过 WaitForReceived 等待之前收到的事件。跨等待后检查 generation 和原 service，关闭连接的旧继续任务失效。PlayerChanged 在主线程捕获角色和会话编号，再通过 ApplyReceived 校验 attempt、Epoch、resume，写入对应当前 Run 和成员；随机角色来源、原始地图和战斗流程不变。

CoopRuntime 的真实断线检测、StopConnection、Pause、场景清理及缺员恢复要求保留。关闭界面仅解除 CoopCareerSession 订阅；已提交的本机操作按原回执完成，关闭会话才取消尚未发送的排队操作。正在存储期间页面仍可滚动和处理原有控件；后续业务操作仍由原 pending 防止重复，不提前宣告操作完成。

多人存档列表与读档使用 ListAsync / LoadAsync，多人导入、导出、删除使用对应异步入口。返回界面时检查控件有效性，删除按钮沿原 pending 防重复；单人生涯存储入口不改。具体输入、发布顺序、检查点和取消范围见[保存与多人同步](PERSISTENCE_AND_COOP.md#客机后台接收与操作顺序)。

实际原版网络验收：独立二人与四人Godot进程，复用原版ENet大厅、消息、地图和战斗服务，验证随机选人、进局、地图一致、战斗行动、倒下后恢复、跨幕、个人同步哈希、暂停/继续及结算。原始正常流程分别101项与171项；实际强制终止二人客机、四人客机后重新加入并继续战斗，四人房主终止后其余三名客机均退出对局并保留检查点；二人和四人所有进程终止后，另起进程恢复原牌组、生命、章节、地图和战斗行动。三轮重复暂停/继续检查任务复用、重复通知不重复切屏、不清除继续提案。测试ENet适配器在连接状态变为Disconnected/Zombie时调用原版HandleClientDisconnection，以产生原版断线通知并移除连接；没有调用已销毁peer的公开断开入口，没有修改生产Steam传输。没有执行真实Steam多账户网络，也没有渲染实际战斗场景。

## 日期推进的实际步骤

CareerEngine.AdvanceOneDay 检查 Failure、PendingMatchId、当日或以前待打且已报名比赛。允许时 MoveToNextDay → PublishMatchDay → CareerStore.Save。

MoveToNextDay 按以下顺序执行：

1. CareerMarket.Initialize 确保行情起点存在，将已过期未报名比赛标成未报名。
2. EsportsWorld.EndDay 处理当天；WeeklyJournal.CloseWeek 捕获期刊事实。
3. Day 加一；SocialAppointments.Expire 更新过期活动。
4. 超过季末时结算赛季、增加 Season、清理较旧赛程，EsportsWorld.StartSeason 建立新赛季。
5. 单人 CareerLife.Advance；ClubOperations.Advance；OwnedClubs.Advance。
6. 发布待公开生活事实、SimulateWorld、AvatarHonors.Capture、CareerCommerce.RefreshOffers。
7. 现代赛事 CircuitWorld.AutoEntry，然后 CareerMarket.Advance 更新当天行情并处理个人账户。

AdvanceToDay 逐天执行以上过程，现有单次循环最多 84 天；遇待处理比赛、失败、待完成对局或到期活动按既有条件停下。finally 在实际推进后发布比赛日事实、压缩积压任务并保存。

跳过四周的测量案例实际只推进一天，原因是到达已确认活动；不能据该案例报告完整四周执行耗时。一天结束后的国际赛事创建与排名处理属于 EndDay / SimulateWorld 的下游，可能同时影响社区与奖励。

## 角色卡编辑与个人态度

OpenCharacterCard 以 CharacterCards.Read 或 New 建立人物草稿；游戏 ID 为空时仅在草稿中填入当前 PublicName，已有 ID 保持。打开或取消窗口不会因此改写原人物。游戏 ID 仍必填。LineEdit 不再设置 MaxLength；Memo 不设字数上限。CharacterCards.Validate 同步取消公开资料和性格描述的长度上限，CareerNames.Validate 的32字校验与 RenamePlayer 的32字提示及128字输入上限也已移除；其余必填、非法字符、重名、数字范围、合同及对局期间编辑规则保持原状。模型 Profile 标记的独立长度规则未改。

只有 NPC 角色卡显示“对你的态度”分页，包含好感 SpinBox（-100—100）、交往关系 TextEdit 和印象 TextEdit。初始值来自当前个人信箱，缺少记录时显示0、初识、空印象；不为了显示初始值建立关系记录。信号注册在初始值设置之后，只有用户输入变化才建立 CharacterCardEdit.Relation，并单独填写对应字段。曾编辑后设回原值仍属于主动覆盖。保存前沿原逻辑调用 SpinBox.Apply，接着单人 Save 或多人 Encode → Send；取消仅关闭草稿。PNG 导出仍只接收人物草稿和头像，导入仍只建立人物。

CharacterCards.Apply(data, edit, relationLife=null, human=null) 先执行完整校验，再沿原路径更新人物。NPC 有 Relation 时调用 PrivateMessages.EditRelation，单人默认使用 data.Life 与 GroupChats.Human；多人规则显式传入提交者的 CoopMember.Life 与 PersonId。该参数只决定个人态度归属，人物资料仍写入共同生涯。共用入口的字段处理与回退说明见[数据约定](DATA_CONTRACTS.md#聊天总结与交互)，提交和失败恢复见[保存流程](PERSISTENCE_AND_COOP.md#角色卡保存与多人归属)。

三项写入后，私信界面读取 PrivateRelation 和 Revision；私信 Context、群聊 Compose、社区 PublicMemory/Persona 与生活活动继续使用现有关系读取入口，没有新增提示词或第二份关系数据。已经开始的模型请求不重新组织或重发；之后有效模型交互仍可按原规则改变三项，完成时使用最新数据。

## 世界俱乐部名录的玩家岗位与点击身份

CareerWorldScreen.ClubDirectory 接收当前 CareerData，按现有俱乐部排序及 _clubLimit 创建名录。只有 data.Esports.ClubId 等于正在显示的俱乐部编号时，才创建本地玩家条目。

岗位文字调用 CircuitScreen.ClubRole(data, club.Id, GroupChats.Human(data))。GroupChats.Human 读取 LocalHumanId；为空时返回单人身份 player。多人个人视图由 CoopRules.View 提供本地成员身份，因此房主和客机分别查询自己的席位。这个调用只读取数据，不保存、不广播、不修改合同、阵容、赛程或版本。

ClubRole 沿用 NPC 的同一入口：自建俱乐部调用 OwnedClubs.Position，依次检查首发、轮换、教练，其他情况显示青训；普通俱乐部检查当前赛季 league 的俱乐部名单，名单内显示本季首发，否则显示轮换选手。兼任教练仍按这个既有顺序显示选手席位。退出首发申请尚未执行时，显示当前席位；新赛季执行后显示新的席位。没有新增字段或旧档迁移。

岗位查询的成员编号与界面点击编号分别使用：PersonLink 的 id 仍为 player，姓名仍由 CareerEngine.Name 提供。PersonLink 创建的头像和姓名按钮沿用 OpenPerson(player)，进入当前本地玩家档案；不将多人成员编号交给原来以 player 表示自己的档案入口。刷新页面时重新读取当前个人视图，没有新增缓存或失效规则。

## 控件缓存的归属与更新

MainMenuEntries.Bind 调用 CareerListCache.For，缓存是当前主菜单的隐藏子节点。主菜单空闲且没有单人/多人生涯界面时，_Process 先按约2毫秒预算分段准备交易终端，再逐帧准备生活导航图标及26种遗物资源，之后准备少量字体字形或一个空人物卡片，默认准备36张；不访问 CareerStore、不加载生涯、不保存、不修改 Font。完成后停止处理。

CareerScreen.OpenView 获取同一缓存。Render、Close、ExitTree 将卡片隐藏并归还，先清空 Open 回调。AddProfileCards 对当前筛选结果重新绑定所有字段、头像身份、人物编号和点击回调。增加显示数量时按需补充空卡片；不缓存人物选择结果。主菜单销毁时一并销毁缓存。

PrivateListRows 只复用当前通讯弹窗内的侧栏按钮。RefreshPrivateList 保留完整排序、筛选编号列表；ShowPrivateListRows 按滚动位置、视口高度重绑按钮，前后保留少量条目。点击读取当前 Id/Group，关闭弹窗后清空列表。私信正文未增加持久气泡缓存，仍使用既有流式增量更新。

CareerVisuals.CreateTheme 缓存模组主题，InterfaceFont 仍引用原版字体且不修改资源参数。Card 在加入场景前指定同一主题，避免临时使用引擎默认字体。字体、颜色、大小、点击入口和选择范围按原实现保留。
