# 文档维护与改动验收

## 章节职责

README 是目录与当前实现的查询入口；MODULES 负责模块边界；DATA_CONTRACTS 负责数据与编号；AI_FLOWS、PERSISTENCE_AND_COOP、GAME_AND_UI 负责各自完整流程；SOURCE_MAP / Source 负责静态双向依赖。性能与验收原始证据保留在维护者本地的 PERFORMANCE 及对应资料中。

开发文档仅记录真实实现、架构、接口、依赖和实测证据，供后续开发查询。方案及未实施设计只在对话中提交审阅，不写入本目录；已经批准但尚未实现的设计也不写入当前流程。

新的业务模块放入职责明确的章节，规模需要时拆为独立专题并从目录链接。已存在功能直接修改原章节，删除过时叙述。版本历史与当前规则分开，避免读者要拼接多次追加记录才能得到现状。

发布与本地安装前同步核对 NationalSpire.json.version 和 Diagnostics.ModVersion，并读取最终 DLL 元数据中的 ModVersion 常量确认构建结果。安装后核对目标目录的清单版本及 DLL、清单 SHA-256。Diagnostics.ModVersion 同时用于 CareerScreen 品牌版本、Entry 加载记录、诊断导出和 CoopRuntime.Compatibility 发布版本标识；修改常量后重新编译整个生产项目，使这些调用者使用同一版本。上述检查在构建与安装阶段执行。

## 开始修改前

1. 阅读目录、负责章节及函数索引，核对源码摘要与当前文件。
2. 从改动函数向上查调用者、信号、委托和游戏补丁入口；向下查返回值、字段、磁盘、网络与界面消费者。
3. 明确哪些值是复制、引用、最新读取、请求快照、历史事实、实时显示或正式结果。
4. 说明具体行为变化、默认处理、限制及单人/多人/旧档范围，提交用户审阅。
5. 从完整操作列出各计算步骤、次数、数据规模、保存和同步节点，确定性能基线与目标。

这一步形成可审阅方案，不修改实现或测试代码。检查中发现需要改设计，重新说明完整方案与行为变化，等待审阅。

## 提示词合并与回归核对

审查涉及模型输出的 PR 时，同时比较可编辑模板、程序固定指令、请求资料、消息顺序、目标识别与合法性检查、解析、预览、效果执行、保存及旧模板转换。作者说明与实际源码行为分别核对，沿输入到保存的完整调用流程确认影响；效果解析代码保持原样，也可能通过提示词或目标检查改变输出及结算。对照当前本地源码与已确认的模型实测记录；PR 能编译或文本冲突已经解决，只能说明相应检查通过。前缀和参与者选择功能与效果目标、效果描述、格式、提示词等改动分别列明审阅范围。当前随机事件的完整流程与实测范围见 [AI_FLOWS.md](AI_FLOWS.md#随机事件流程)，源码入口为 RandomEventPrompts.Compose、PromptLibrary.Get/EditableText、RandomEventParser、RandomEventEffects 及 PrivatePublicContext。以下是当前实现中已经形成的核对项目。

| 核对对象 | 当前行为与已有修正 |
| --- | --- |
| 创作模板和固定格式 | 玩家编辑 world/event 创作模板；程序追加逐行 JSON 格式和效果说明。旧自建模板与缺少 event 的旧 JSON 继续采用现有补齐和转换入口。LegacyInitialFormat、LegacyEffects 及其组合 Format 保留识别旧模板所需的原文，新增说明写入实际请求入口。 |

| 自由行动结局 | 前两条消息沿用 Compose 的相同组织方式，随后追加原标题、故事、Continuation 和玩家行动；模型仅生成 result/effects，行动文字直接取玩家输入。保留已批准的50—200字指导和延续上文文风、叙述口吻及人物语言的要求，续写请求省去原选项及其预写结局、效果。 |
| 文本前缀缓存 | world/event 每次通过当前模板查询入口读取；模板、玩家资料战绩、Materials 和 PublicPosts 相同时，首次与续写的前两条消息逐字相同。区分可复用前缀与服务实际报告的缓存命中，已有验证仅证明逐字相同的部分。 |
| 世界观和卡牌资料 | 随机事件读取 world 并追加 WorldGuidance；世界观维持社会背景、人物认知和实力尺度，生活题材围绕人物、处境和情感展开，卡牌、怪物及打法按情节需要使用。聊天卡名检索附有语境说明，日常同名词按原意理解。 |

| 私聊、群聊、帖子及总结 | Materials 保存参与人物资料、关系、ChatTimeline 会话总结、最近20项私聊/群聊及共同经历、检索的社区材料及正文和评论上下文；PublicPosts 保存选取的近期玩家公开原帖正文。续写实际传入这些资料，沿用现有来源编排与帖子去重。国家九项指标、当天安排、经济、库存、商品、品牌及有关俱乐部继续由原资料入口提供。 |
| 人物目标 | 提示词引导使用本次参与者的 NPC 编号，空名单创作单人事件；结算也接受参与名单外、存档中现有可交流 NPC，并将所选效果人物补入经历记录。人物编号、商品编号、品牌编号和国家名称采用本轮资料，格式示例只解释字段。 |

合并审查逐项记录实际差异、对应调用者和旧档影响。需要改变上述行为时，按既有代码审阅规则说明并取得批准。验证采用真实组装后的完整消息，分别核对默认模板、玩家自定义模板、旧 JSON、首次故事、自由行动和试写；可复用现有检查时沿用同一入口。涉及创作指令或资料组织的改动，沿已有授权范围调用模型，对照完整回复、解析效果和玩家可见结果。保留已经确认的请求与回复证据，记录模型、模板、输入来源及验证边界；离线检查与真实模型验收分别说明。

## 每项变更必须填写的内容

以下内容写入该功能的负责章节，取代原实现说明，不复制成一份尾部更新日志。

| 项目 | 要说明的问题 |
| --- | --- |
| 实现目的 | 已实现的行为解决什么问题；适用范围和现有边界是什么 |
| 输入 | 由哪个函数/字段/事件提供；数据什么时候形成；是否可能在等待期间变化 |
| 调用 | 准确函数名、调用条件、顺序；委托/事件/反射目标；重复执行条件 |
| 输出 | 返回值与修改字段；谁继续使用；是否还会进入帖子、记忆、总结或下一轮 |
| 数据归属 | 单人实例、房主最新数据、个人视图、客户端、本机配置各自负责什么 |
| 保存 | 每次保存含什么变化；谁依赖保存后状态；原版文件是否参与 |
| 同步 | 完整快照和流式字段；接收权限、版本、顺序、检查点、界面刷新 |
| 失败与离开 | 原有取消、失败、重试和恢复；请求期间跨天、开赛、切换或退出怎样处理 |
| 兼容 | 旧字段缺失、旧模板、历史记录、身份变化、已有进行中对局怎样处理 |
| 性能 | 全部计算阶段、次数、各次/最大耗时、累计与总耗时、分配及线程影响 |
| 验证 | 同输入基线、优化后差异、业务副作用、文件/网络/界面、极端中断、真实或替身环境 |
| 缺口 | 尚未验证的具体入口与运行条件；不使用模糊的“已全面验证” |

## 索引的维护

每个 Source 文档记录源码 SHA-256，函数保留签名、输入默认值、返回类型、调用者、调用与字段引用。模块移动、函数签名和调用变化时，同时更新双向文件关系与相关函数条目。类拆成 partial 后仍按源码文件定位。

生成索引使用 Roslyn 语义绑定，不通过函数同名匹配猜测目标。分析范围包括类型、字段初始化、参数、返回类型、方法组、函数调用及属性引用。nameof 是编译期名称表达式，不计函数执行。局部函数以所在声明位置区分；匿名函数计入所属函数。自动索引是查找入口，不代替流程说明。

索引使用 Roslyn 语义绑定生成，方法记录保留在维护者本地的 INDEX_GENERATION.md。生成过程只输出 Markdown 文档，不编译生产模组、不执行游戏。新增隐式构造函数、接口动态派发、委托目标、运行时反射和游戏补丁须在流程中明确，不把“没有直接调用者”理解为没有使用者。

修改前后检查：源码摘要匹配；函数与文件链接有效；调用者与被调用者两侧一致；负责章节没有互相冲突；不存在“方案”混写为“现有实现”。

## 性能验证与正确性验收

每项新功能或修改都执行与实际影响范围匹配的性能测试。架构阶段先识别次数随资料规模或成员数增长的地方，避免先引入逐人全量复制、逐字重建、重复序列化，再把更改成本留给后续修复。

纯数值、文案等影响明确、效果直观的小改动，仅执行必要的编译、针对性检查和性能确认，不重复全量复杂回归。涉及保存、同步、解析、数据结构或流程变化时，再扩大验证。已有可复用测试继续保留，调整数值时同步维护相应预期。

性能优化必须分别证明：输入选择未变；输出和保存状态符合批准范围；同步可见性与顺序未变；原恢复机制仍能处理失败或中断；整体耗时满足目标。解释意图与静态代码检查不代替这些证据。

纯性能项比较完整上下文、候选顺序、随机状态、解析结果、业务变化、保存字段和每人广播权限。含明确业务修改时，只允许出现已批准差异，单列其余等价检查。

所有量化结论注明构建、源码摘要、数据规模、环境、测量边界、样本次数、逐次/最大值和未测部分。出现新的超过目标步骤，要记入完整流程，不能从报表移除。

## 日志增长与诊断完整性验收

本模组全部自动日志遵守工作区 AGENTS.md 的日志增长与诊断完整性规则。适用对象包括普通运行、模型请求与返回、解析与交互检查、比赛、保存恢复、多人收发、错误及性能记录，同时检查内存队列、缓存、临时文件和未完成传输。玩家主动导出的诊断 ZIP 由玩家管理。

修改前从磁盘写入和内存累积入口核对全部来源，再向上检查调用者、向下检查轮换、读取、导出和多人收集。逐项说明增长约束、保留范围、轮换条件、完整记录及操作关联；数值依据实际规模和保留需求提交审阅。所有自动日志复用统一的日志管理入口。

诊断内容须对应具体生涯、事件或对局、生成或重试次数、阶段和时间，并包含排查所需的实际输入、原始返回、解析或判定结果与错误。保存恢复须记录入口条件、跳过原因、完成结果和实际检查点。导出及多人收集完整覆盖已批准保留范围，传输总量限制不得截断或拒收诊断内容；失败或缺失须明确列出。

日志及传输修改须保证游戏、记录和导出继续正常执行。容量、长度和人为防御条件不得触发强制截断、报错或失败；临时写入及传输异常在后台静默处理，保留完整资料并恢复未完成操作。处理状态和真实错误写入诊断记录，界面与游戏操作继续运行。具体恢复行为须在实施前说明并经用户批准。

验收同时核对长期连续写入、不断创建新文件、单条大记录、重复错误、重新生成、生成及解析失败、退出重启、切换生涯、旧记录兼容和完整导出。涉及多人时验证客机收集、传输中断及重连。记录磁盘占用、文件数量、内存与耗时，比较原始输入和最终导出内容，列出实际覆盖范围、保留边界和未验证条件。本节为维护与验收要求，当前各入口的实现仍以负责章节和源码为准。

当前实现由 LogStorage 统一管理普通、随机事件和比赛三类日志，每类当前加四份历史，完整记录写入后在下一条之前轮换；固定性能文件覆盖写入。新增日志必须复用该入口，并检查对应内存容器、导出、多人收集和退出释放。保留范围外的较早记录随轮换到期；导出时完整读取保留范围。写入暂不可用的队列范围、重试及统计见 DATA_CONTRACTS。容量审计、逐项压力测试与性能原始资料位于维护者本地 LOG_DIAGNOSTIC_VERIFICATION.md；该原始验收文件不随公开架构文档发布。

## 完成与长期维护

完成报告链接当前章节与实测证据。没有执行真实模型、真实网络、游戏或故障中断，就明确写未执行。没有达到目标，就记录未达到，不用其他场景的改善代替。

文档维护与功能修改是同一项工作的组成部分。会话摘要保留目录位置、已批准范围、当前实现、未完成验证；后续先读文档和源码再继续。当前章节需要表达可以直接查到的事实，不能把用户此前纠正当作唯一记忆来源。

Development 中已获授权的架构、接口、维护规则与源码依赖索引可以公开，具体文件以 .gitignore 逐项放行的路径为准。内部审阅、未实施方案、性能验收原始资料、索引生成工具、玩家存档及凭据不公开，不强制加入 Git。

PR 必须同步修改受影响的流程章节、数据约定和函数条目，更新双向调用关系及源码摘要；不能仅在文档末尾增加版本记录。实现相同规则的各入口必须复用同一负责模块，具体要求见[贡献说明](../CONTRIBUTING.md#模块复用与长期维护)。
